# AGENTS.md

This file provides guidance to Qoder (qoder.com) when working with code in this repository.

## Project Overview

sta-blog-ui is a personal blog frontend built with Vue 3 + Vite + TypeScript + Pinia + Element Plus + SCSS. It supports both online (API-driven) and offline (static JSON fallback) modes.

## Commands

```bash
# Install dependencies (pnpm)
pnpm install

# Dev server (port 50011)
pnpm dev

# Production build (vite build + static page generation)
pnpm build

# Regenerate API client + enum constants (requires backend running on localhost:48080)
pnpm openapi

# Generate static data for offline mode (requires old backend)
npx tsx src/utils/generate-static-data.ts [backend-url]

# Full-text search index (pagefind)
pnpm page
```

No lint or test scripts are configured.

## Architecture

### Dual API Layer (Migration in Progress)

The project is migrating from an old blog backend to a Ruoyi-based backend:

- **`src/api/`** (NEW) — Auto-generated by `@umijs/openapi` from the Ruoyi backend OpenAPI spec (`blog-app` group). Each file maps to a Java Controller (e.g., `AppArticleController.ts`). Types live in `src/api/typings.d.ts` under the `API` namespace. Uses `src/utils/request.ts` as the adapter layer (unwraps `{code, msg, data}` → `data`). **Do not hand-edit these files**; regenerate via `pnpm openapi`.

- **`src/apis/`** (OLD, being deprecated) — Hand-written API modules that call the old blog backend directly. These use old endpoint paths (e.g., `/article/list`, `/comment/getComment`). Most are still referenced by views; migration to `src/api/` is ongoing.

When adding new API calls, prefer adding them to the Ruoyi backend and regenerating `src/api/`. Only add to `src/apis/` as a temporary workaround.

### Request & Auth Chain

```
http.ts (axios instance, baseURL=/api)
  ├── request.ts (adapter for @umijs/openapi, unwraps CommonResult)
  ├── auth.ts (JWT token get/set/refresh via localStorage/sessionStorage)
  └── Interceptors:
        - Request: auto-attach Bearer token, loading indicator for specific paths
        - Response: 401 → auto refreshToken with queue, retry original request
```

- Token storage: JSON object `{accessToken, refreshToken, expiresTime}` under key `"Token"`
- JWT prefix: `"Bearer "` (defined in `src/const/index.ts` as `JWT_PREFIX_CONS`)

### Vite Proxy Configuration

| Frontend Path    | Proxied To                          | Purpose               |
|------------------|-------------------------------------|-----------------------|
| `/api/app-api`   | `VITE_YUDAO_SERVE` (localhost:48080)| Ruoyi backend (new)   |
| `/wapi`          | `VITE_MUSIC_SERVE`                  | Music service          |

Old `/api` proxy to the legacy backend is commented out in `vite.config.ts`.

### Offline Demotion (useDemotion)

`src/composables/useDemotion.ts` performs a health check on app startup. If the backend is unreachable, the app falls back to reading static JSON files from `public/` via `src/utils/file-reader.ts`. Stores and views use the `requestOrRead()` pattern:

```ts
const { requestOrRead, isOnline } = useDemotion()
await store.getInfo(requestOrRead)  // online → API call, offline → local JSON
```

### Layouts

Two layout modes controlled by route meta:

- **BaseLayout** (`meta.headerType: "home"|"page"|"none"`) — Header + main-content (74%) + main-sidebar (26%) + Footer. Used for Home, Category, Tags, Timeline, Message, Link.
- **CustomLayout** — Minimal Nav + bare content area + optional Footer. Used for Article detail, About, User auth, TreeHole, Music, Photo. Pages manage their own header/sidebar.

Reading mode (`useReadingMode`) hides Nav, Footer, and FloatingMenu for distraction-free article reading.

### State Management (Pinia)

| Store               | File                        | Purpose                            |
|---------------------|-----------------------------|------------------------------------|
| `article`           | `useArticleStore.ts`        | Current article detail + visit tracking |
| `user`              | `useUserStore.ts`           | Auth token + user info             |
| `website`           | `useWebsiteStore.ts`        | Site info + article title list for search |
| `pagination`        | `usePaginationStore.ts`     | Article & comment pagination state |
| `search`            | `useSearchStore.ts`         | Search dialog visibility + history (localStorage) |

### Type System

- `src/api/typings.d.ts` — Generated `API` namespace with all VO types (e.g., `API.AppArticleRespVO`)
- `src/types/index.ts` — Convenience re-exports and legacy types (`ArticleVO = API.AppArticleRespVO`, `CommentVO = API.AppCommentRespVO`, etc.)
- `src/const/index.ts` — **Auto-generated** by `scripts/gen-enum-consts.ts` from OpenAPI enum schemas. Contains `BlogType`, `ArchiveType`, and local constants (`JWT_PREFIX_CONS`, `TOKEN_KEY`). Do not hand-edit the generated section.

### Auto-Imports

`unplugin-auto-import` and `unplugin-vue-components` are configured:
- Vue/VueRouter/Pinia APIs are auto-imported (no need to import `ref`, `computed`, `onMounted`, etc.)
- Element Plus components are auto-registered
- Type declarations: `src/types/auto-imports.d.ts`, `src/types/components.d.ts`

### Custom Directives

- `v-slide-in` — Scroll-triggered slide-in animation (`src/directives/vSlideIn.ts`)
- `v-lazy` — Lazy loading (`src/directives/vLazy.ts`)
- `v-view-request` — Request on element visibility (`src/directives/vViewRequest.ts`)

### SCSS

- Global variables: `src/styles/variable.scss` (injected via `additionalData` in vite config — available in all `.vue` and `.scss` files without `@use`)
- Layout breakpoints/mixins: `src/styles/mixin.scss`, `src/styles/_layout.scss`
- Path alias: `@` → `src/`

### OpenAPI Code Generation Pipeline

`pnpm openapi` runs two steps:
1. `openapi2ts.config.ts` — Fetches `http://localhost:48080/v3/api-docs/blog-app`, generates `src/api/*.ts` + `src/api/typings.d.ts`
2. `scripts/gen-enum-consts.ts` — Reads enum schemas from the same OpenAPI spec, generates enum constants in `src/const/index.ts`

File naming: Controller class prefix from `operationId` (e.g., `AppArticle_getArticle` → `AppArticleController.ts`). Function naming: part after `_` (e.g., `getArticle`).

### Static Data & Pagefind

- `src/utils/generate-static-data.ts` — Fetches all data from old backend, saves encrypted JSON to `public/apis/` and `public/articles/`
- `src/utils/generate-article-pages.mjs` — Generates static HTML pages for SEO (runs as part of `pnpm build`)
- Pagefind full-text search index lives in `public/pagefind/` and `src/pagefind/`
- `src/config/config.ts` — `ENCRYPTION: true` controls whether static data is encrypted (`.enc` files)
